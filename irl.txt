### Etapas Bem Definidas para Implementar o Plano de IRL

Com base no conteúdo original de `irl.txt`, aqui estão as etapas sequenciais e bem definidas para começar a implementação. Elas estão organizadas por fases principais: preparação, desenvolvimento do simulador IRL, integração de dados, atualização do frontend e testes. Cada etapa inclui objetivos claros, arquivos envolvidos e dependências.

#### Fase 1: Preparação e Análise (1-2 dias)
1. **Analisar dados IRL existentes**: Revisar os arquivos CSV em `IRL_DATA/` (ex.: `sensor_data_20240927_150526.csv`) para confirmar os campos disponíveis (GPS, AHRS, acelerômetro) e identificar lacunas (RPM, gear, throttle %, etc.). Verificar se os dados seguem o formato `RiderData`.
   - Arquivos: `IRL_DATA/sensor_data_*.csv`
   - Ferramenta: Usar scripts Python em `ml/` para análise inicial.

2. **Definir perfis de motocicleta**: Criar um arquivo de configuração com perfis (ex.: Scooter, Naked) incluindo relações de marcha, limites de RPM e física básica.
   - Arquivo: Novo `simulador_irl/motorcycle_profiles.json` ou similar.
   - Base: Usar lógica existente de `simulador/config.py`.

#### Fase 2: Desenvolvimento do Simulador IRL (3-5 dias)
3. **Criar simulador IRL básico**: Desenvolver `simulador_irl/enhanced_simulator.py` baseado em `simulador/headless_simulator.py`. Implementar funções para calcular RPM, throttle %, temperatura do motor e voltagem a partir de dados IRL.
   - Funções-chave: `calculate_rpm_from_speed()`, `estimate_throttle()`, `simulate_engine_temp()`, `simulate_voltage()`.
   - Dependências: Integrar com `routes.py` e `config.py` do simulador existente.

4. **Adicionar lógica de física**: Implementar simulação realista usando dados de aceleração e velocidade para estimar throttle e RPM. Incluir variações de ruído para dados como voltagem.
   - Arquivo: `simulador_irl/enhanced_simulator.py`
   - Teste: Criar script de teste em `simulador_irl/test_enhanced_simulator.py` com dados de exemplo.

5. **Gerar dados aprimorados**: Modificar o simulador para processar um CSV IRL e gerar um `EnhancedRow` com todos os campos de telemetria.
   - Saída: Novo formato CSV ou estrutura de dados compatível com o simulador virtual.
   - Opção: Suporte para processamento em lote ou em tempo real.

#### Fase 3: Integração de Dados e Backend (2-3 dias)
6. **Atualizar CSV Parser**: Modificar `app/backend/src/csvParser.ts` para incluir opção de aprimoramento de dados. Integrar chamada ao simulador IRL (via API ou processamento local).
   - Arquivo: `app/backend/src/csvParser.ts`
   - Lógica: Adicionar flag `enableEnhancement` e chamar `enhanced_simulator.py` durante o parsing.

7. **Integrar com backend**: Garantir que o backend possa executar o simulador IRL como etapa de pré-processamento. Armazenar dados aprimorados em memória durante a simulação.
   - Arquivo: `app/backend/index.js` ou similar.
   - Dependências: Verificar compatibilidade com `prisma.config.ts` se necessário.

#### Fase 4: Atualização do Frontend (3-4 dias)
8. **Criar componente TelemetryOverlay**: Desenvolver `TelemetryOverlay.tsx` para exibir métricas (velocidade, RPM, gear, etc.) como overlay no vídeo.
   - Arquivo: Novo `app/frontend/src/components/TelemetryOverlay.tsx`
   - Estilo: Semi-transparente, posicionável, com campos customizáveis.

9. **Atualizar VideoPlayer**: Modificar `VideoPlayer.tsx` para aceitar props de telemetria e renderizar o overlay.
   - Arquivo: `app/frontend/src/components/VideoPlayer.tsx`
   - Props: Adicionar `telemetryData` e controle de visibilidade.

10. **Modificar RealSimulator**: Atualizar `RealSimulator.tsx` para passar dados da linha atual para o VideoPlayer e adicionar controles de toggle para o overlay.
    - Arquivo: `app/frontend/src/pages/RealSimulator.tsx`
    - Integração: Conectar com dados processados do backend.

#### Fase 5: Testes e Validação (2-3 dias)
11. **Testar simulação IRL**: Executar o simulador com dados reais e validar se os campos calculados são realistas (ex.: RPM baseado em velocidade e marcha).
    - Ferramenta: Scripts em `simulador_irl/tests/`
    - Métrica: Comparar com dados virtuais do simulador existente.

12. **Testar integração frontend-backend**: Verificar se o overlay aparece corretamente no vídeo e se os dados são atualizados em tempo real durante a reprodução.
    - Ambiente: Usar `docker-compose.yml` para testar localmente.
    - Cenários: Play/pause/seek com dados IRL.

13. **Testes de performance**: Garantir que o aprimoramento de dados não cause atrasos significativos. Medir tempo de processamento para CSVs grandes.
    - Ferramenta: `vitest.config.ts` ou scripts manuais.

#### Fase 6: Documentação e Deploy (1-2 dias)
14. **Atualizar documentação**: Revisar `README.md` e `IMPLEMENTACAO_GPX_ML.md` para incluir instruções sobre o simulador IRL e overlays.
    - Arquivos: `README.md`, `irl.txt` (atualizar com progresso).

15. **Deploy e validação final**: Testar em ambiente de produção (usando Docker) e validar com dados IRL reais.
    - Comando: `docker-compose up` com dados de `IRL_DATA/`.

Essas etapas assumem familiaridade com Python (para simulador), TypeScript/React (para frontend) e Docker. Comece pela Fase 1 para evitar dependências circulares. Se encontrar bloqueios, priorize testes unitários em cada etapa.
